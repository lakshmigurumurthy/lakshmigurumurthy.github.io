Enterprise AI · Personalization

Agent Memory

Agent Memory is a conversational memory capability for supported Salesforce Agentforce agents. It lets an agent remember useful details, such as a user's preferences, across separate conversations so the person doesn't have to start from scratch each time. Administrators enable the capability, and users can opt in and manage remembered information in supported experiences.

MY CONTRIBUTION

Turned a complex new capability into clear guidance on who enables memory, when it starts, what users control, and how to import or manage stored information.

Documentation delivered: Administrator setup and user-control guidance · Import Memories task · Memory-management action references · Release notes.

Target audience

Salesforce administrators and Agentforce users

Documentation scope

Concepts, configuration, considerations, tasks, action references, release notes

Explore documentation decisions and process

Customer challenge

Without conversational memory, an agent may lose useful context between sessions, forcing people to repeat preferences or background information. The feature addresses that friction while making user choice and memory controls important parts of the experience.

Documentation challenge

The documentation needed to explain a new concept without conflating administrator settings, individual user consent, stored memories, and the agent's behavior. Support also varies by agent type and channel, so seemingly small wording differences could mislead customers.

Role & contributions

Led the evolution of administrator-focused Agent Memory guidance, from the core feature explanation to setup controls, user opt-in, supported experiences, memory import, and management actions. Turned changing requirements and technical discussions into distinct concept, task, and reference content, and refined the guidance for general availability and later enhancements.

Documentation approach

01Discover

Worked with product and engineering to clarify memory capture, permissions, supported experiences, and import behavior.

02Structure

Built a reader-focused content structure that separated what administrators configure from what individual users control, with dedicated task guidance for memory import and management.

03Author & validate

Authored and revised DITA-based Help and release communication, checked behavior with product and engineering, and clarified experience-specific differences, including the absence of a Memory panel in Experience Cloud.

04Publish

Coordinated editorial reviews and release-aligned updates as memory capabilities became available.

Customer value

The documentation connects the purpose of memory to concrete administrator and user decisions, helping readers understand when memory is available, how it is controlled, and how to use or manage it.

AI capabilities · Technical reference

Agentforce Standard Actions

Agentforce Standard Actions are ready-to-use capabilities that an AI agent can invoke to perform a specific operation. For example, Web Search retrieves information from the web, Speech to Text converts an audio file into text, and Text to Speech turns text into spoken audio. These actions let agent builders add functionality without designing every operation from scratch.

MY CONTRIBUTION

Translated engineering specifications into usable action references that tell builders exactly what each action does, which inputs it accepts, and what it returns.

Documentation delivered: Web Search, Speech to Text, and Text to Speech references · Inputs, outputs, limits, formats, and provider options.

Target audience

Agent builders and Salesforce administrators

Documentation scope

Action references, inputs, outputs, constraints, release notes

Explore documentation decisions and process

Customer challenge

Agent builders need reliable, reusable capabilities, but must know which action fits their use case, what information to provide, and what result the action returns.

Documentation challenge

Each action has a different technical contract. Audio actions involve file types, size limits, languages, and output formats; web search involves providers and domain controls. Inaccurate or hard-to-find details can lead to failed configurations.

Role & contributions

Owned and maintained technical reference content for Web Search, Speech to Text, and Text to Speech. Translated action contracts into builder-oriented descriptions of purpose, inputs, outputs, supported formats, limits, and configuration options, including changes to web-search providers and domain restrictions.

Documentation approach

01Research

Reviewed action specifications and clarified supported file formats, limits, parameters, provider behavior, and expected outputs with engineering and product partners.

02Structure

Used consistent reference patterns so builders can quickly compare what each action does, which inputs it accepts, and what it returns.

03Validate & publish

Reviewed technical details and updated content as action capabilities evolved.

Customer value

Helps builders select the right action, supply valid inputs, anticipate outputs, and avoid preventable configuration errors.

Before suggesting changes, the priority was understanding how the screens connected and what customers needed to accomplish.

04 / Workflow innovation

Streamlining UX Content Reviews with AI

When major features brought large volumes of UI text across several Figma files, preparing Google Docs for CX approval became a repetitive, time-consuming task, especially across concurrent projects.

The manual bottleneck

Copy labels, descriptions, error messages, and other UI text from Figma, organize them in Google Docs, and build comparison tables for existing and suggested wording, project after project.

The AI-assisted solution

Developed a reusable skill using Claude Code and Cursor to extract labels, descriptions, error messages, and other UI text directly from Figma and organize it into structured, review-ready tables.

What the review-ready output looked like

DescriptionExisting guidanceSuggested revision

2–3×Estimated productivity improvement

The reusable workflow reduced manual review preparation across multiple projects, leaving more time to evaluate clarity, terminology, consistency, and the customer experience. Content recommendations, editorial judgment, and CX approvals remained human-led.

The takeaway: By automating time-consuming tasks with AI, the UX writing process became more efficient and scalable, allowing greater focus on content quality, consistency, and delivering a better user experience.
